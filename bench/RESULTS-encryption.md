## What was measured

The same fixture through three backends in one process, in one container:

* `plain` — `BackendKind::Local`;
* `convergent` — `BackendKind::Encrypted { Convergent }` over `Local`;
* `random` — `BackendKind::Encrypted { Random }` over `Local`.

Fixture: one large file, a small-file set and an identical duplicate pair,
generated by a deterministic xorshift fill (synthetic bytes, not model
weights). Each repetition starts from an empty store, writes every file
(one commit per file), records backend counters, drops the handle, reopens
read-only, reads and compares every object back, and records the physical
footprint of the store directory. Seven repetitions, arms **interleaved inside
every repetition** (`plain`, `convergent`, `random`), so a slow minute of the
host lands on all three arms.

CPU is `getrusage(RUSAGE_SELF)` user+sys around each phase, in the same
process. The read phase is warm page cache by construction (the file was just
written), so it measures decode + envelope CPU, not media.

## The dedup tradeoff, as measured

| fact | observed |
|---|---|
| equal plaintext → equal ciphertext, convergent | `true` |
| equal plaintext → equal ciphertext, random | `false` (two seals differ) |
| re-publishing the same name + plaintext, convergent | idempotent no-op |
| re-publishing the same name + plaintext, random | `Exists` conflict |
| stored object count, all three arms | identical |
| physical footprint, convergent vs random | identical |

**The leak that is not hidden.** The WeftFS blob name is the plaintext content
hash, in every mode. `random` makes ciphertext bags of bytes differ, but two
tenants storing the same chunk still land on the same object path, and the
store's dedup still collapses them, which is why the footprint and object count
in the table are the same for all three arms. Anyone who can list the object
namespace learns equality of content; anyone who can also read a header in
convergent mode gets a direct confirm/deny oracle for a candidate plaintext
(hash the candidate, compare). This court therefore claims **neither**
confidentiality nor cross-tenant dedup protection beyond what the table shows:
convergent keeps dedup and leaks equality; random drops ciphertext-level dedup
and still leaks equality through the name.

## Losses

* Write wall and write CPU roughly double (see ratio rows): the envelope is
  extra CPU on the critical path and there is no hardware offload.
* Read wall and read CPU rise by more than the write ratio for `convergent`,
  because the plaintext hash is recomputed on every open.
* Footprint grows by the fixed header plus one tag per block, and that applies
  to manifests as well as to chunk objects.
* `random` costs the same as `convergent` to write while giving no ciphertext
  dedup and no namespace privacy — it is not a free upgrade.
* A wrong key makes the newest published state unopenable; the store refuses
  the open (`Unauthorized`) instead of serving an older generation. That is a
  deliberate refusal, and it means a lost key is a lost store, not a degraded
  one.
* A revoked key is `Unauthorized` even though the secret is still in the key
  file: revocation is a retention decision, not a rotation.

## Not claimed

one container, `tmpfs` data. No cryptographic review. No Go or Python
implementation of the envelope. No claim about the control plane (commit
records stay plaintext) and no claim of confidentiality against a key holder.
